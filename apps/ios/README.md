# The iOS shell

Capacitor over WKWebView. Android gets a Trusted Web Activity instead, and the
two are not interchangeable — read `AGENTS.md` before changing anything here
that a shell can see.

## What it actually is

It loads `https://www.loveplusone.app` into a WKWebView. It does not bundle the
app, because there is no bundle to make: `apps/web` is server-rendered Next.js
with server actions and a cookie-bound Supabase session, and none of that
survives being served off the filesystem. The `public/` directory in here holds
one page — the thing the member sees when the site cannot be reached.

Capacitor's own type declarations call `server.url` "not intended for use in
production". That warning is about App Store review rather than about anything
breaking, and it is recorded in `PROJECT_UPDATES.md` rather than treated as
handled. Read the long comment at the top of `capacitor.config.ts` before
assuming this shape was chosen carelessly.

## Running it

Xcode is required and its Simulator runtime is a **separate download** — the
current Xcode ships as a ~2 GB shell with no bootable iOS image in it:

```bash
xcodebuild -downloadPlatform iOS      # ~8 GB, once
```

Then, from this directory:

```bash
pnpm sync        # copy public/ and capacitor.config.ts into the Xcode project
pnpm open        # open it in Xcode
```

`CAP_SERVER_URL` overrides the origin the shell loads. It has to be **https** —
a plain-http dev server needs an App Transport Security exception that this
project deliberately does not ship, so point it at a preview deployment or a
tunnel rather than at `localhost:3000`.

## What is hand-written in `ios/`

`ios/` is generated by `npx cap add ios`, and re-running that on an existing
checkout would overwrite work that is not recoverable from any config file:

- **`ios/App/App/Info.plist`** — the camera and microphone purpose strings,
  without which iOS terminates the app the moment the liveness check asks for
  the camera; the portrait lock that matches `manifest.ts`; and `arm64` in place
  of the template's `armv7`. Every one of those has a comment saying why.
- **`ios/App/App/Assets.xcassets`** — the app icon and launch image, written by
  `scripts/generate-icons.mjs` from the same mark as the web icons. Regenerate
  with `node scripts/generate-icons.mjs`; do not edit the PNGs.

Everything else in `ios/` is Capacitor's, and `ios/.gitignore` already excludes
what is generated per-build. `.prettierignore` keeps the formatter out of the
whole directory, for the reason written down in it.

## Not wired yet

- **Native push.** `push_subscriptions.platform` already accepts `'ios'`, and
  `nativePlatform()` in `apps/web/src/lib/native-shell.ts` already returns it —
  the web half has been waiting for this shell since it was written. Nothing
  registers with APNs, so the shell today gets web push or nothing.
- **Store billing.** 15% via StoreKit, per the 2026-08-24 decision. No StoreKit
  code exists.
